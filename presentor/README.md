# Presentor application

This is an application to demonstrate the TRNG created in this project. It serves a rudimentary web app, providing an adjustable RNG.

## Usage
The environment variables:
- `TARGET_ADDR`: the base address of the server (for testing, an arbitrary HTTP address may be used, which could be generated from https://postb.in). This must only be set on Linux, as only the Linux executable will query the TRNG.
- `SERVER_ADDR`: the address which the server should serve at. Usually, `127.0.0.1:8000` is sufficient, except when exposure to other devices is wanted. In that case, the address should be set to the local computer's IP address

must be set and visible to the executable.

A stable installation of Rust is required for compilation, which may be obtained [here](https://rust-lang.org/tools/install/).

The server may be started with `cargo r` for debugging or `cargo r --release` for a release version. An executable is obtainable via `cargo b (--release)` (where `--release` is optional).
The files in the `static/` directory will be served at the root of the specified server address (`SERVER_ADDR`). An additional route, `GET /mixer?start=<start>&stop=<stop>` is provided by the server which returns a JSON object in the form of:


```json 
{
  "code": <code> // in the range of <start> and <stop>
}
```

The server "mixes" data generated by the TRNG with the system's entropy pool to provide an always accessible flow of random data. It is only compilable on Linux platforms due to the server using the `ioctl(RNDADDENTOPY)` operation, which may not be available on other platforms.

The server however, is available on non-Linux platforms as well, however the server will not be queried and therefore, no entropy will be added to `/dev/random`.

The server may be enabled/disabled by specifying or omitting the `mixer` feature in `cargo` commands:
```sh
cargo r -F mixer
cargo b -F mixer
...
```
